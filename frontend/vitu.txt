Purpose of main.py
main.py is the heart and launcher (App Entry Point) of your entire Python FastAPI backend. When Uvicorn runs uvicorn app.main:app, this file is executed. It performs:

System logging initialization (setup_logging()).
MongoDB database connection initialization during server startup (lifespan).
Automated background cron scheduler initialization (schedule_midnight_admin_email_task()).
Global HTTP middleware registration (Request Logger & CORS origin rules).
Global exception handlers registration (register_exception_handlers).
Routing configuration (Mounting all API routes under /api/v1).
Server health monitoring endpoints (/health).

3. The Midnight Cron Task Function (Lines 20 – 44)
Actual Code:
python
async def schedule_midnight_admin_email_task():
    """Background task running continuously: triggers daily sales & stock report email to all admins at 12:00 AM midnight."""
    logger.info("Initializing Midnight 12:00 AM Automated Admin Report Scheduler...")
    while True:
        try:
            now = datetime.now()
            tomorrow = now + timedelta(days=1)
            midnight = datetime(year=tomorrow.year, month=tomorrow.month, day=tomorrow.day, hour=0, minute=0, second=0)
            seconds_until_midnight = (midnight - now).total_seconds()
            
            logger.info(f"Next automated 12:00 AM Admin Email Report scheduled in {seconds_until_midnight:.0f} seconds.")
            await asyncio.sleep(seconds_until_midnight)
            from app.api.v1.admin.reports import dispatch_daily_report_to_all_admins
            result = await dispatch_daily_report_to_all_admins(requested_by_email="Automated 12:00 AM Midnight Cron")
            logger.info(f"[12:00 AM MIDNIGHT CRON] Automated Daily Report emailed to {len(result.get('admin_emails_notified', []))} admins!")
            await asyncio.sleep(60)
        except asyncio.CancelledError:
            logger.info("Midnight Admin Report Scheduler task cancelled.")
            break
        except Exception as e:
            logger.error(f"Error in midnight admin report scheduler: {e}")
            await asyncio.sleep(300)
Explanation:
Why it exists: To automatically calculate sales, revenue, low-stock items, and pending orders every night at 12:00 AM midnight and email a PDF/HTML report to all store admins without human intervention.
Parameters: None.
Return Value: None (coroutine).
Who calls it: Called inside lifespan() (Line 51) using asyncio.create_task().
What it calls:
dispatch_daily_report_to_all_admins() inside app.api.v1.admin.reports. (Notice it is imported dynamically inside the function at Line 33 to prevent circular import crashes during backend startup!).
Step-by-Step Logic:
while True: -> Starts an infinite loop running in the background for the entire lifetime of the server.
now = datetime.now() -> Reads current system date and time.
tomorrow = now + timedelta(days=1) -> Calculates tomorrow's date.
midnight = datetime(year=..., hour=0, minute=0, second=0) -> Constructs exact target timestamp for 12:00 AM midnight tonight/tomorrow.
seconds_until_midnight = (midnight - now).total_seconds() -> Calculates how many seconds the server needs to wait. (e.g., if it is 8:00 PM now, seconds_until_midnight = 14,400 seconds).
await asyncio.sleep(seconds_until_midnight) -> Crucial non-blocking pause. Pauses this specific background coroutine while leaving the rest of FastAPI completely free to handle customer requests.
await dispatch_daily_report_to_all_admins(...) -> Fetches admin emails from MongoDB, generates sales/stock metrics, and emails them out via Resend.
await asyncio.sleep(60) -> Waits 60 seconds so it doesn't trigger twice within the same midnight minute.
except asyncio.CancelledError: -> Handles clean task termination when the server shuts down (cron_task.cancel()).
except Exception as e: -> Catches unexpected errors (e.g., database network drop), logs the error, and sleeps for 300 seconds (5 mins) before trying again.
4. The Lifespan Context Manager (Lines 46 – 56)
Actual Code:
python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup tasks
    logger.info("FastAPI lifecycle startup: Connecting database client.")
    await db_manager.connect()
    cron_task = asyncio.create_task(schedule_midnight_admin_email_task())
    yield
    # Shutdown tasks
    cron_task.cancel()
    logger.info("FastAPI lifecycle shutdown: Disconnecting database client.")
    await db_manager.disconnect()
Explanation:
Decorator @asynccontextmanager: Converts an async generator function into an ASGI context manager that FastAPI uses to manage application lifecycle events.
Why it exists: Replaces old deprecated @app.on_event("startup") and @app.on_event("shutdown") decorators in modern FastAPI.
Parameters: app: FastAPI (The main FastAPI application instance).
Return Value: Generator yielding execution to FastAPI during server runtime.
Step-by-Step Logic:
Before yield (Startup Phase):
await db_manager.connect() -> Connects Motor client to MongoDB Atlas and initializes Beanie ODM models (User, Product, Order, etc.).
cron_task = asyncio.create_task(...) -> Schedules the 12:00 AM midnight report scheduler running in the background without blocking server boot.
yield: Server starts listening for HTTP traffic! FastAPI executes incoming requests while paused at yield.
After yield (Shutdown Phase):
Triggered when you press Ctrl+C or Render stops the server container.
cron_task.cancel() -> Stops the 12:00 AM midnight scheduler loop gracefully.
await db_manager.disconnect() -> Closes MongoDB connection pool safely without leaking connection handles.

@app.get("/health", tags=["Health"], ...)
async def health_check() -> JSONResponse:
    """Production-ready health check verifying service status and MongoDB connectivity."""
    db_connected = False
    try:
        if db_manager.client is not None and db_manager.db is not None:
            await db_manager.db.command("ping")
            db_connected = True
    except Exception as exc:
        logger.warning(f"Health check MongoDB ping failed: {exc}")
        db_connected = False
    if db_connected:
        return JSONResponse(
            status_code=status.HTTP_200_OK,
            content={"status": "ok", "db_connected": True},
        )
    return JSONResponse(
        status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
        content={"status": "unhealthy", "db_connected": False},
    )
Explanation:
root_endpoint() (GET /): Serves a basic welcome message confirming that the web server is online.
health_check() (GET /health):
Used by Render, Docker, and uptime monitoring services to check if your backend is healthy.
Internal Logic: Runs await db_manager.db.command("ping") to verify live MongoDB Atlas responsiveness.
If MongoDB responds -> Returns HTTP 200 OK ("db_connected": True).
If MongoDB ping fails or throws an exception -> Catches the error, logs a warning, and returns HTTP 503 Service Unavailable ("db_connected": False).

C. Interview Questions from main.py
Q1: How do you handle database connections during application startup and shutdown in FastAPI?
Answer: In modern FastAPI, we use the @asynccontextmanager lifespan handler passed to the FastAPI(lifespan=lifespan) application instance. Before yield, we initialize our MongoDB client (await db_manager.connect()), and after yield, we close connections (await db_manager.disconnect()) during server shutdown.

Q2: How do you run background scheduled tasks in FastAPI without blocking incoming HTTP requests?
Answer: We spawn an asynchronous coroutine using asyncio.create_task(coroutine_function()) inside the startup phase of the lifespan context manager. Inside the coroutine, we use an infinite while True loop with await asyncio.sleep(seconds). Because asyncio.sleep yields control back to the event loop, FastAPI handles incoming user traffic concurrently.

D. Possible Interviewer Traps
Trap 1: "Why didn't you use @app.on_event("startup")?"
Correct Answer: @app.on_event("startup") and @app.on_event("shutdown") are deprecated in newer versions of FastAPI. The official recommended pattern is using the lifespan async context manager.
Trap 2: "If your 12:00 AM cron task crashes, will it crash your whole FastAPI web server?"
Correct Answer: No. The task is wrapped in a try...except Exception block inside the while True loop. If an error occurs, it logs the exception, waits 300 seconds, and continues the loop without crashing the main application thread.
